## New-lever research: RAG pipelines — chunk-overlap (stride) dedup

### Hypothesis

`docs/rnd/fundamentals/rag-context-rightsizing.md` (literature review, 2026-10-28)
ranks **T1: retrieved-chunk overlap / duplicate de-duplication** as the best-fit,
black-box, no-model lever on the RAG axis — near-lossless, because RAG indexers
chunk source documents with an *overlapping* stride (10–20% is a common default;
Databricks' own long-context RAG benchmark used 512/256 = 50%), so two adjacent
retrieved chunks placed in the same prompt repeat a byte-for-byte identical run of
sentences even though the two chunks are **not** identical as wholes.

2026-10-24's RAG work (`docs/rnd/2026-10-24-NOTES.md`) already shipped the
*exact-duplicate-excerpt* case — the same whole chunk retrieved twice,
joined by a single newline — by extending `dedupeRepeatedBlocks` to match
at line granularity as well as block granularity. That is a different,
narrower case than T1: it only fires when a whole line is byte-identical
to another whole line. The overlap case T1 actually describes is two
chunks that are **not** identical as wholes — only a sub-span (the stride
overlap) repeats — and a retrieved chunk is normally formatted as one
unbroken line of prose, so the two overlapping runs never align on a line
boundary for `dedupeRepeatedBlocks` to match at all. Confirmed empirically
below (`duplicateContext` never fires on the new fixture).

### What was built

1. **`packages/core/src/token-reduction.ts`**: new exported reducer
   `dedupeOverlappingSentences(minimumSpanTokens = 12, countTokens)`. Splits
   text at sentence boundaries (end punctuation + whitespace, or a newline —
   the same cheap heuristic as the existing research sandbox,
   `evals/fundamentals/rag_context_rightsizing.py`), and drops any sentence
   whose exact bytes were already kept earlier in the same text, using a
   global `seen` set so a duplicate is caught regardless of which chunk it
   first appeared in. Same safety rules as `dedupeRepeatedBlocks`: exact
   byte match only (whitespace differences are never merged), fenced/inline
   code is masked out and never touched, first occurrence always survives
   verbatim, and only spans at or above `minimumSpanTokens` count (a lower
   default than `dedupeRepeatedBlocks`'s 24, since a sentence is a shorter
   unit than a block).
2. **`packages/sdk-js/src/reduce-request.ts`**: new config flag
   `chunkOverlapDedup?: boolean | { minimumSpanTokens?: number }`, applied
   in `reduceText` right after the existing `duplicateContext` step, with
   its own change record (`lever: "chunk-overlap-dedup"`, `lossless: true`).
   **Off by default** (unlike `duplicateContext`) because it is new tonight
   and not yet measured on real traffic beyond the simulator — opt in
   explicitly, same posture `crossTurnMemoryDedup` shipped with on its first
   night, even though this one is lossless and that one is not.
3. **`packages/sdk-js/src/theo-policy.ts`**: registered `chunk-overlap-dedup`
   in `applyLever`, `knownLeverIds()`, and `ENFORCEABLE_LEVERS`, so Theo's
   coverage dashboard honestly lists it as an `available` candidate rather
   than silently omitting a lever the proxy can actually apply. Not added to
   `defaultPolicy()` (same posture as `stale-history-compaction`, which is
   also lossless but not in the fresh-user default) — it is a new, unadopted
   lever, not yet a default.
4. **Tests**: 7 new cases in `packages/core/src/token-reduction.test.ts`
   (cross-chunk overlap removal, untouched when no duplicate, first
   occurrence kept verbatim, short-sentence floor, code-fence protection,
   whitespace-difference protection, idempotence) and 6 new cases in
   `packages/sdk-js/src/reduce-request.test.ts` (off by default, catches
   what `duplicateContext` alone misses, tunable minimum, invalid-input
   skip-not-throw, no-op when nothing repeats, never mutates the caller's
   request). All green; full suite now 537/537 (was 523/523).
5. **`evals/run-rag-chunk-overlap-dedup.ts`** (new): a realistic RAG fixture —
   6 synthetic source documents, each sliding-window chunked into 10-sentence
   excerpts at a configurable stride, 40 one-shot queries each retrieving 3
   adjacent chunks from one "relevant" document (the overlap source) plus 2
   unrelated chunks from two other documents (no overlap). Two scenarios:
   TYPICAL (stride 8 → 20% overlap) and HIGH (stride 5 → 50% overlap,
   Databricks' own rate). Arms: **A** raw/no MESH, **B** today's existing
   lossless stack (`toolSchemas` + `duplicateContext` + `repairCachePrefix`),
   **C** B + `chunkOverlapDedup`. All three priced with caching unavailable —
   the shape's one stable span (the system prompt) sits below Anthropic's
   1,024-token cacheable minimum, confirmed by MESH's own
   `cache-ttl-suppressed` guard firing on every request, so a cache-policy
   choice this shape can never actually use is kept out of the comparison
   (same practice as `run-memory-agent-dedup.ts`).

### Measured

```
node --import tsx evals/run-rag-chunk-overlap-dedup.ts
```

| scenario | B vs A (existing stack) | C vs B (chunkOverlapDedup alone) | C vs A (full stack) |
|---|---|---|---|
| TYPICAL (20% stride overlap) | 0.0% | **6.5%** | 6.5% |
| HIGH (50% stride overlap, Databricks-style) | 0.0% | **15.6%** | 15.6% |

Both numbers are **qualified lossless wins** by this project's own standard
(only exact, byte-identical repeated sentences are ever dropped; every
surviving sentence is byte-identical to what was sent before) — not a
"candidate pending replay-gate," unlike most of the memory-agent work.
`duplicateContext` fires zero times on this fixture in arm B, confirming the
hypothesis that the existing stack does not reach this shape at all.

### Honest limits (read before publishing anywhere)

- **Not a published number.** This is an internal R&D eval
  (`evals/run-*`), not cited in `README.md` or `docs/site/evidence.md`. Per
  `evidence.md`'s own standard, a published figure is "independently
  re-verified by a checker separate from the implementer" — that has not
  happened here, so nothing in the published tables should change tonight.
- **Sentence-boundary assumption.** The fixture builds chunks on sentence
  boundaries, so every overlapping span in it is a whole-sentence exact
  match — precisely the case this lever is built to catch. A real indexer
  that windows by raw character/token count (common in practice) will
  sometimes cut mid-sentence; the overlapping run then becomes a
  *near*-duplicate rather than an exact one, and this lever will not touch
  it (by design, to stay strictly lossless). **The 6.5% / 15.6% figures are
  an upper bound for that class of indexer, not a floor.** This is exactly
  the caveat `rag-context-rightsizing.md` already flagged for T1 in the
  abstract; tonight's numbers give it a concrete (synthetic) magnitude for
  the first time.
- **Still simulator-measured, synthetic fixture.** No real retrieved-chunk
  dataset was sampled tonight (no network access in this environment to
  pull a HF RAG dataset). `rag-context-rightsizing.md`'s own "what to
  measure next" item 1 (overlap/duplicate rate on real retrieved blocks) is
  still open — see below.
- **`PUBLISHED_LEVERS` (`packages/core/src/savings-model.ts`), the catalogue
  Theo's separate coverage oracle (`theo-coverage.ts`) measures against, was
  NOT updated tonight.** That catalogue carries literature-sourced
  reduction-factor projections and segment-targeting logic; registering a
  new lever there correctly is a larger, separate task left for a future
  night rather than rushed in alongside the implementation.

### Quality-gate / replay-gate status

None needed, by the same reasoning `duplicateContext` and 2026-10-24's
line-level extension needed none: every byte that survives is byte-identical
to text the model already received once in the same message. This stays in
the lossless bucket by construction.
