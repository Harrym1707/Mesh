## New-lever research: continuous-memory agents (founder mandate shape 3)

Picked up the item `2026-10-23-NOTES.md`, `2026-10-24-NOTES.md`, and
`2026-10-25-NOTES.md` have each in turn flagged as **owed for three
consecutive nights**: `crossTurnMemoryDedup` (shipped 2026-10-23, off by
default, classified LOSSY) has a reproducible 58.0% token/cost candidate on
the memory-agent shape, but nothing had ever graded it on anything beyond
"the bytes are identical." `2026-10-23-NOTES.md`'s own proposal was "an
LLM-judge grader comparing real model responses with the memory block
present once vs restated every turn... to get SOME quality signal beyond
the bytes are identical." There is still no live API budget or customer
traffic in this environment (same constraint every night since 10-23), so a
real LLM-judge grader was not possible tonight either. What was built
instead is as close an honest substitute as that constraint allows, using
the house's own existing gate machinery rather than hand-rolling a new one.

### What was built

1. **`evals/memory-dedup-fixture.ts`** — a new memory-agent fixture, because
   the existing one (`run-memory-agent-dedup.ts`'s `memoryAgentStream()`,
   and `run-workload-matrix.ts`'s `memoryAgent()`) has nothing to grade:
   every turn asks a generic "handle today's request N," so there is no
   notion of a right or wrong answer. This fixture's turns each ask about
   **one specific fact** drawn from an 8-fact memory block, across 30
   independent 8-turn conversations (240 requests), so a grader can ask "is
   the fact THIS turn needs actually recoverable from the request MESH
   sent?"

2. **A modeled, explicitly-labelled recall-probability proxy**
   (`recallProbability()` / `estimateRecall()` in the same file), because
   `crossTurnMemoryDedup` never deletes the fact — turn 1's copy is always
   left verbatim — so the fact is present somewhere in every arm, and a
   presence-only grader (the house's `exactTextGrader` style) would pass
   every arm vacuously and say nothing about the actual risk the lever's own
   doc comment names. The proxy instead scores a continuous, modeled
   "recall probability" from WHERE the needed fact ends up: near-ceiling
   (0.985) when it sits immediately before the question (every turn, in the
   lossless-no-dedup arm), and a primacy plateau (0.93, eroding mildly as
   the whole transcript grows, floored at 0.55) when it instead sits pinned
   at the very head of a growing conversation — which is structurally where
   `crossTurnMemoryDedup` leaves it after turn 1. **This is a toy curve
   inspired by the qualitative shape long-context recall studies report
   (near-ceiling at the very start or end of context, worse in the middle);
   its constants are NOT calibrated to any real provider or model and must
   never be read as a measured number, published, or cited as production
   proof.** The module's own doc comment repeats this at length precisely
   so nobody downstream drops the caveat by copying the number out of
   context. The constants were fixed before the script was ever run once,
   and were not tuned afterward to move the verdict either way.

3. **`evals/run-replay-gate-memory-dedup.ts`** — wires that fixture through
   the EXISTING `replayGate` + custom `ReplayGrader` machinery
   (`packages/sdk-js/src/replay-gate.ts`), the same house infrastructure
   `run-replay-gate-freshcap.ts` already uses to gate `freshToolResultCap`.
   Two candidates: a sanity candidate (lossless stack, no dedup — should
   cost nothing beyond the proxy's own ceiling-below-1.0 and save no
   tokens, confirming the grader isn't buggy) and the real candidate
   (lossless + `crossTurnMemoryDedup`). `metadata.requiredFact` is threaded
   through each request (the same pass-through convention
   `run-replay-gate-freshcap.ts` uses for its own task/turn metadata) rather
   than keyed by object identity, because `reduceRequest` returns a new
   object (`{ ...request }`) for a reduced request — an identity-keyed
   lookup would silently miss every candidate call.

4. **12 new tests**, `evals/memory-dedup-fixture.test.ts`: fixture shape
   (task/turn count, every required fact genuinely present in the memory
   block, metadata survives independent of object identity), the
   array-vs-string content flattener (the same `wire()`-shape pitfall
   `2026-10-23-NOTES.md` flagged for future eval authors), last-occurrence
   lookup (not first — the most recent, most favourably-positioned copy),
   and the recall curve's monotonicity/bounds. 523 → **534 tests**.

### Measured result

`node --import tsx evals/run-replay-gate-memory-dedup.ts`, house default 2%
quality budget, grouped-bootstrap-bounded exactly like `freshcap`'s gate:

| candidate | token saving | mean Δquality | lower-95 Δquality | verdict |
|---|---|---|---|---|
| lossless stack (no dedup) — sanity | 0.0% | −1.50pp | −1.50pp | REJECTED (nothing to enable — correct: no lever here has anything to compact on a fixture with no tools and no cache stamp) |
| lossless + `crossTurnMemoryDedup` | 40.5% | −6.52pp | −6.70pp | **REJECTED** — lower bound breaches the 2.00pp limit |

The sanity candidate's exact, repeatable −1.50pp (the proxy's own
ceiling-minus-one, identical on every one of 240 requests, zero bootstrap
variance) is the grader behaving exactly as designed, not a defect — it
confirms the ceiling is 0.985, not 1.0, and that the gate's quality-bound
plumbing produces a sane number before the real candidate is read at all.

**Under this modeled proxy, the gate rejects `crossTurnMemoryDedup` on the
continuous-memory-agent shape.** The 58.0%/40.5% token saving is real and
reproducible (confirmed again, independently, by this script's own
provider-usage accounting); the quality risk this proxy assigns to it is
not survivable at the house's default 2% budget. This is reported exactly
as measured, in keeping with the mandate's own rule that a lever losing the
quality gate counts as a finding against it, not something to tune away —
the curve's constants were set once, before the first run, and were not
touched afterward.

### Honest limits of tonight's result — read before citing it anywhere

- **This is a bound under a labelled, uncalibrated proxy, not a
  replay-gate pass on real traffic or a real LLM's output.** It answers
  "does this candidate clear the budget under a stated modeling
  assumption," not "is this safe to bill." `crossTurnMemoryDedup` was
  already off by default and ungated; nothing here changes its
  configuration or any published number — it stays exactly where it was,
  a documented, tested, OFF-by-default candidate.
- A REJECT here is read as a real reason to keep the lever off pending a
  genuine replay-gate run (real LLM-judge or customer traffic) — not
  evidence that drops the matter. An APPROVE would equally only have meant
  "the toolchain is ready," never "it may be billed" — the script's own
  closing output says this explicitly so a future reader who only pastes
  the table does not miss it.
- The proxy's one structural limitation worth naming: because
  `dedupeRepeatedLeadingBlock` always anchors the canonical copy at turn 1
  (position zero of the whole conversation), this fixture only ever
  exercises the curve's **primacy** plateau, never its **middle-of-context**
  trough — the worst case long-context literature reports. If a future
  integration pattern ever let the anchor drift away from position zero
  (not something the current implementation does), this proxy would
  silently understate the risk there.
